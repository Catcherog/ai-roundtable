## 安装与首次打开

**Windows 10/11 x64**　完整解压 `AI-Roundtable-Windows-x64.zip`，进入 `AI-Roundtable` 文件夹，双击 `AI-Roundtable.exe`。主程序、内置 Python、.NET 和前后端文件需要保存在一起。若首次启动报告缺少 WebView2，请安装微软的 Evergreen 运行时。[微软官方下载](https://developer.microsoft.com/microsoft-edge/webview2/)

**Apple 芯片 Mac**　需要 macOS 12 或以上。确认 `python3 --version` 至少为 3.9，解压 `AI-Roundtable-macOS-arm64.zip`，将 `AI圆桌.app` 拖入「应用程序」。本版使用本地签名，未作 Apple 公证。首次打开遇到来源验证提示时，请核对下载来源和校验值，再参考 [Apple 官方说明](https://support.apple.com/zh-cn/102445)。

两种平台都需要先安装至少一个支持的 CLI 并在终端完成登录。若使用 npm 安装，保留 Node.js 和 CLI 的安装目录。要核对下载文件，可在 Windows 使用 `Get-FileHash 文件名.zip -Algorithm SHA256`，在 macOS 使用 `shasum -a 256 文件名.zip`，对照发行页的 `SHA256SUMS.txt`。

**从 v4.0.2 升级：先备份，再启动。** 在打开新版前彻底退出旧版，复制整个 `~/.ai-roundtable/`（Windows：`%USERPROFILE%\.ai-roundtable`）到另一个位置；如果自己设置过 `AI_ROUNDTABLE_HOME`，请备份那个目录。不要只复制数据库，附件也在数据目录里。5.5.1 保存时裁剪至最近 50 场，整场重写时仅保留最近 500 条发言，删除会议不能从回收站找回。受管文件超过 128 MiB 的项目请选择较小的子目录。若需保留旧行为，可以[继续使用 v4.0.2](https://github.com/Catcherog/ai-roundtable/releases/tag/v4.0.2)；仅换回旧程序并不能找回已裁剪的数据。

## 配置 1–6 个席位

按 **Ctrl+,**（Windows）或 **⌘,**（Mac）打开设置，在「阵容与称呼」选择参会席位，在「席位与模型」设置驱动、模型和推理档位，点「保存配置」。重新打开设置可以查看保存的值。「并发实测连通」会向所选驱动发起真实请求。可用模型取决于 CLI 版本和账号，可执行文件路径可在「驱动与诊断」指定。

| 现有环境 | 配置方法 |
| --- | --- |
| 只装了一个 CLI | 可让多个席位使用同一驱动，在「并发与时限」里设置同时运行的通道数。 |
| 装有多个 CLI | 给席位分别选择驱动，先在终端验证各自能回答问题，再在圆桌中测试。可选驱动包括 Antigravity、Codex、Claude Code、Grok 和 Ollama。云端工具按账号授权；Ollama 需事先准备本地模型。 |
| 只想找一个人讨论 | 选择「单席专注」，也可以点击席位职责标签，调整参会状态和角色。 |

看到席位名称或检测到程序路径，说明圆桌找到了可执行文件。连通测试收到的实际回复，可以进一步验证模型、账号和网络。多个席位共用账号时都会占用对应服务的额度。

## 从议题到纪要

1. **选一个场景。** 有两个选项时，点开场页的「方案利弊红蓝辩证包」；看界面截图选「产品体验与多模态走查包」，审代码选「工程研发与代码审查包」。只想快速听个意见，也可以展开阵容预设，选「单席专注」。
2. **输入一个可以做决定的问题。** 初次使用可照抄[首页的待办 App 取舍题](../README.zh-CN.md#第一场会就问一道有取舍的题)，点「开始研讨」。真实评审时把时间、资源和什么情况下算失败也写进题目。
3. **让追问与交锋有落点。** 交叉互评会自动为每条实质质疑分配 `D1..Dn` 编号：被质询席若「接受修正」即直接更新终态契约；若主张「量化反证拒改」，圆桌会自动唤醒原质询席做短验收，防止自说自话销账。你也可以在白板风险项上点「双席再辩 1 轮」，或用 `@席位名` 点名追问。需要看源码时，输入 `@` 搜索文件并支持 `:起始行-结束行` 精确行段引用。
4. **整理白板与溯源精华。** 共识、风险与任务支持手工增改，右侧「跨席互认思想精华」与「已淘汰方案负面清单」会自动归集本场碰撞出的跨席亮点与废案；点击条目即可跳回原发言卡片核对上下文。将风险「采纳为共识」会移入共识栏；取消勾选任务会将它排除在本轮执行范围之外。
5. **形成自包含决议并导出。** 本轮结束后点「形成决议」，主笔会基于倒序终态快照起草 6 段式决议，再由其余席位对照自身原稿块级会签补漏。点击决议卡片上的 **「复制决策包」** 可直接复制纯净自包含决策文本（含差集守卫自动补录的漏项代码契约，不含冗长原始聊天流水）；点击顶部 **「复制纪要」** 或 **「导出 .md」** 则同时附带完整原始发言全录。若形成决议后你又发起了追问或再辩，导出的决策包会在顶部自动置顶最新变更增量并提示重算决议。

「重开本议题」会清空这场会议旧发言并重新研讨。想保留原会议做对照时，使用「新建」另开一场。

## 执行与回滚

进入右侧「执行终端」，核对执行席位、绑定的目录和已勾选的任务。默认选中的「只读预演」用于先看实施建议或补丁。开启自动预演也会使用只读模式。

需要实际落盘时，选择「写入工作区」，再启动执行。圆桌为绑定目录内的受管文件建立快照，包括一般被 Git 忽略的普通文件；未纳入 Git 跟踪的 `output/` 和 `.app` 目录不纳入快照。绑定前会检查受管普通文件总量，超过 128 MiB 时拒绝绑定并提示较大的目录。Git 项目和普通目录均可恢复受管文件，回滚不会撤销 Git 提交、远端推送或工作区外的副作用。执行后若有文件又被手动编辑，圆桌会列出冲突并保留当前内容。Windows 遇到目录联接等重解析点会在写入前提示，请使用普通本地项目目录。

快照保存在本机。写入过程意外中断时，重新打开应用后可按恢复提示核对受影响的文件，再决定是否恢复。

## 源码运行与目录

Windows 使用 PowerShell 7 和 .NET 8 SDK。在仓库根目录运行 `pwsh -File scripts/build_windows.ps1`，产物在 `dist/windows/AI-Roundtable-Windows-x64.zip`。构建时会下载 Python 官方嵌入版和 WebView2 SDK。

在 macOS 上，从源码启动浏览器界面：

```bash
git clone https://github.com/Catcherog/ai-roundtable.git
cd ai-roundtable
bash scripts/start_web.sh
```

Web 模式默认绑定本机回环地址，按 `Ctrl+C` 停止本次运行。需要构建桌面版时，先安装 Apple Command Line Tools，然后在仓库根目录执行：

```bash
bash scripts/build_macos_app.sh
open ./AI圆桌.app
```

| 位置 | 内容 |
| --- | --- |
| `backend/` | 本地 HTTP 服务、实时事件、席位编排、CLI 适配、SQLite 存储和工作区快照 |
| `frontend/` | 讨论界面、白板、源码引用、执行终端和会议纪要导出 |
| `macos_app/` | Cocoa 窗口、WKWebView 和原生菜单 |
| `scripts/check_cli.py` | 自检入口。`--bench` 使用模拟回复覆盖讨论流程；不带参数还会向实际 CLI 发起请求 |
| `~/.ai-roundtable/` | 本机设置、会议历史、探测缓存和运行日志。可以在退出应用后备份这个目录 |

## 常见问题

**能直接用网页版 AI 的登录状态吗？** 圆桌调用本机 CLI。先在终端走通该 CLI 自己的登录与问答，再回到设置里实测。桌面包不包含模型服务。

**会议一直等，怎么区分慢和失败？** 查看席位的运行状态和错误详情。可以跳过本席当前回合，其他席位继续。要结束整场当前运行，点击「停止运行」；需要时可在失败卡片上重试或调整设置。

**绑定项目后，哪些东西送进模型？** 工作目录、项目结构摘要和显式引用的源码可能进入讨论上下文，底层 CLI 也可能按其权限读取文件。首次体验可以用空项目或公开示例。界面和历史在本机运行，联网请求由各 CLI 按其配置发出。

**桌面版卡在启动页怎么办？** 先在终端检查 `python3 --version`，再查看 `~/.ai-roundtable/backend_boot.log`。页面能开但模型没回复时，优先检查 CLI 登录、模型名称和实际连通测试结果。

**怎样反馈一个能复现的问题？** 在 Issue 里写清 Windows 或 macOS 版本、使用的 CLI、讨论策略、最短操作步骤，以及预期和实际结果。附上脱敏后的错误提示即可。[提交 Issue](https://github.com/Catcherog/ai-roundtable/issues)
