# AI 圆桌使用手册

[返回项目首页](../README.md) · [下载 Mac 版](https://github.com/Catcherog/ai-roundtable/releases/latest/download/AI-Roundtable-macOS-arm64.zip) · [English overview](../README.en.md)

## 安装与首次打开

发布包适用于 Apple 芯片 Mac。可在苹果菜单的「关于本机」里查看芯片型号。本版二进制的最低构建目标为 macOS 12，发布前的实机验证环境为 Apple 芯片、macOS 27.0.1。桌面窗口启动后，会从登录 shell 的环境启动 Python 本地服务。

1. 在终端运行 `python3 --version`，确认版本为 3.9 或更高。准备并登录一个受支持的 CLI，先直接用它问一个简单的问题，确认当前账号有模型访问权限。
2. 从发行页下载 `AI-Roundtable-macOS-arm64.zip` 并解压，将 `AI圆桌.app` 拖入「应用程序」。桌面包自带前后端，无须运行编译脚本。
3. 首次打开可能遇到 macOS 的来源验证提示。本版采用 ad-hoc 签名，尚无 Developer ID 公证。确认文件来自本仓库后，可以按 Apple 的说明在「系统设置 → 隐私与安全性」中允许这一次打开。[Apple 官方说明](https://support.apple.com/zh-cn/102445)
4. 如需核对下载内容，把发行页的 `SHA256SUMS.txt` 和 ZIP 放进同一目录，在该目录运行 `shasum -a 256 -c SHA256SUMS.txt`。显示 `OK` 表示下载内容与发布时一致。

## 配好一个或三个席位

按 **⌘,** 打开设置，选择各席位使用的驱动、模型和推理档位。列表中的名称是预设，真实可用的模型取决于 CLI 版本和账号。点击「实测模型连通」会发起实际请求，确认收到回复后再保存。应用也支持为席位指定可执行文件的完整路径。

| 现有环境 | 配置方法 |
| --- | --- |
| 只装了一个 CLI | 点击「应用单引擎多角色配置」，检查三个席位的驱动与模型，再做连通测试。三个角色可以对同一问题提出不同意见。 |
| 装有多个 CLI | 给席位分别选择驱动，各自在终端完成登录，再在圆桌中测试。可选驱动包括 Antigravity、Grok 和 Codex。 |
| 只想找一个人讨论 | 选择「单席专注」，也可以点击席位职责标签，调整参会状态和角色。 |

看到席位名称或检测到程序路径，说明圆桌找到了可执行文件。连通测试收到的实际回复，可以进一步验证模型、账号和网络。多个席位共用账号时都会占用对应服务的额度。

## 从议题到纪要

1. **输入一个可以做决定的问题。** 初次使用可照抄首页的水果投票题。做真实评审时，补上约束和验收标准，例如「导出的任务要能区分已勾选和未勾选，第一次上线只支持 Markdown」。
2. **选讨论深度。** 需要尽快得到方案就选「快速合议」。已有两种方案时，用「正反辩证」要求先论证再反驳。代码问题可以选择「源码诊断」场景并绑定项目。
3. **让追问有落点。** 用 `@席位名` 指定回答者，或在白板风险项上点「定向讨论」。需要看源码时，输入 `@` 搜索文件，可以继续加上 `:起始行-结束行`。界面会显示选中的引用范围。
4. **整理白板。** 共识、风险与任务可以手工添加和编辑。开会前写下的约束会带入第一轮。将风险「采纳为共识」会把它移入共识栏；取消勾选任务会将它排除在本轮执行范围之外。
5. **形成决议并导出。** 等本轮结束后点「形成决议」，需要时将决议条目同步至白板。「复制纪要」可用于粘贴，「导出 .md」生成文件。桌面版优先保存到「下载」目录并提示路径，浏览器版走浏览器下载。纪要包含完整研讨记录，分享前可以删去不适合公开的内容。

「重开本议题」会清空这场会议旧发言并重新研讨。想保留原会议做对照时，使用「新建」另开一场。

## 执行与回滚

进入右侧「执行终端」，核对执行席位、绑定的目录和已勾选的任务。默认选中的「只读预演」用于先看实施建议或补丁。开启自动预演也会使用只读模式。

需要实际落盘时，选择「写入工作区」，再启动执行。Git 工作区会记录本次执行前后的工作区和暂存状态。执行结束或中止后，只要有可恢复的变更，就可以点「回滚写入」。如果同一文件在执行结束后又被你改过，圆桌会指出冲突并保留当前内容。后续只读预演可保留上一轮写入的回滚入口。

回滚覆盖 Git 跟踪的文件和未被忽略的新文件。Git 忽略的文件、仓库外文件和外部服务操作不属于恢复范围。每个会话只保留最近一次可回滚的写入快照，关闭应用后快照失效。非 Git 目录也能执行写入，但没有这一键回滚能力。

## 源码运行与目录

```bash
git clone https://github.com/Catcherog/ai-roundtable.git
cd ai-roundtable
bash scripts/start_web.sh
```

Web 模式默认绑定本机回环地址，按 `Ctrl+C` 停止本次运行。需要构建桌面版时，先安装 Apple Command Line Tools，然后在仓库根目录执行：

```bash
bash scripts/build_macos_app.sh
open ./AI圆桌.app
```

| 位置 | 内容 |
| --- | --- |
| `backend/` | Python 标准库实现的本地 HTTP 服务、实时事件、席位编排、CLI 适配与 Git 快照 |
| `frontend/` | 讨论界面、白板、源码引用、执行终端和会议纪要导出 |
| `macos_app/` | Cocoa 窗口、WKWebView 和原生菜单 |
| `scripts/check_cli.py` | 自检入口。`--bench` 使用模拟回复覆盖讨论流程；不带参数还会向实际 CLI 发起请求 |
| `~/.ai-roundtable/` | 本机设置、会议历史、探测缓存和运行日志。可以在退出应用后备份这个目录 |

## 常见问题

**能直接用网页版 AI 的登录状态吗？** 圆桌调用本机 CLI。先在终端走通该 CLI 自己的登录与问答，再回到设置里实测。桌面包不包含模型服务。

**会议一直等，怎么区分慢和失败？** 查看席位的运行状态和错误详情。可以跳过本席当前回合，其他席位继续。要结束整场当前运行，点击「停止运行」；需要时可在失败卡片上重试或调整设置。

**绑定项目后，哪些东西送进模型？** 工作目录、项目结构摘要和显式引用的源码可能进入讨论上下文，底层 CLI 也可能按其权限读取文件。首次体验可以用空项目或公开示例。界面和历史在本机运行，联网请求由各 CLI 按其配置发出。

**桌面版卡在启动页怎么办？** 先在终端检查 `python3 --version`，再查看 `~/.ai-roundtable/backend_boot.log`。页面能开但模型没回复时，优先检查 CLI 登录、模型名称和实际连通测试结果。

**怎样反馈一个能复现的问题？** 在 Issue 里写清 macOS 版本、使用的 CLI、讨论策略、最短操作步骤，以及预期和实际结果。附上脱敏后的错误提示即可。[提交 Issue](https://github.com/Catcherog/ai-roundtable/issues)
