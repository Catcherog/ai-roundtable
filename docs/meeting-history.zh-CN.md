# 历史会议与跨窗口记忆

## 4.0.2 的使用方式

圆桌按会议编号保存历史。同名会议各有独立的记录。在历史列表点开原会议，可以接着看发言、白板、已提交的附件和项目绑定。搜索框可按会议标题或议题查找。会议列表按最近更新时间排序。

| 用户操作 | 结果 |
| --- | --- |
| 发送议题、完成发言或更新白板 | 圆桌自动保存。消息完成和阶段收尾会写入本机数据库，部分更新合并写入。手动导出 Markdown 可另存一份供阅读的纪要。 |
| 关闭窗口或重启后打开原会议 | 读取已保存的记录。上次中断的发言保留已有内容并标记中断，主持人可以决定是否重试。输入框里尚未发送的文字属于该窗口的草稿。 |
| 两个窗口连接同一个圆桌服务，打开同一场会 | 两边看到同一条发言流和白板。在一个窗口追加的发言或主持约束，另一个窗口会收到更新。断线后按事件序号续接，必要时重新读取会议快照。 |
| 打开另一场会 | 使用那场会自己的议题、发言和白板。模型与账号配置可以共用。每次推理会在上下文预算内选取本场相关资料，重要决定适合固定在白板。 |
| 点击历史列表中的删除按钮 | 核对会议标题和提示，确认后移入「最近删除」。发言、白板、已上传附件和归档备份继续保留。没有自动清空期限。 |
| 在「最近删除」点「恢复」 | 原编号回到历史列表，重新打开即可接续。恢复期间会保留其他会议及当前窗口的选择。 |
| 在「最近删除」点「永久删除」 | 第一次点击只展开清理说明。须输入完整会议标题，再点「确认永久删除」。取消、输错标题、旧的确认请求都不会开始清理。 |

正在研讨、执行，或有项目恢复、可回滚快照待处理的会议，需先结束相应操作或处理快照，再移入最近删除。重开本议题会清空该会议的原发言和白板，圆桌会另外确认。希望保留两轮记录时可新建一场会议。

## 数据归属与删除范围

| 数据 | 保存位置与生命周期 |
| --- | --- |
| 会议编号、标题、席位、发言、白板和执行结果 | 默认位于用户主目录的 `.ai-roundtable/state.sqlite3`。活动列表或最近删除状态写入同一数据库。保存和恢复完整发言时取消旧版 50 场会议、每场 500 条及当前执行日志 300 条的裁剪。 |
| 已上传的附件 | 保存到 `.ai-roundtable/attachments/<会议编号>/`。普通删除保留附件，永久删除清理该会议的上传副本。 |
| 会议专属的项目修改备份 | 保存到 `.ai-roundtable/backups/<会议编号>/`，另有执行恢复记录。永久删除会清理该会议所属的备份与恢复记录。 |
| 项目源文件、上传前的原文件、已导出的纪要 | 归用户选择的工作区或导出位置管理，会议删除操作仅处理圆桌数据目录内的上述内容。模型供应商和操作系统另行管理的记录有各自的生命周期。 |

Windows 默认数据目录为 `%USERPROFILE%\.ai-roundtable`，Mac 为 `~/.ai-roundtable`。使用独立数据目录的实例各自保存。跨窗口共享的适用范围是连接同一服务并打开同一会议。跨设备、外部 AI 聊天窗口、独立运行的另一套后端不属于本版实时协作范围。

## 保存、恢复和升级规则

- 保留会议编号和发言顺序。已存在的数据库在原表添加最近删除状态，升级后所有原有行仍然可读。首次从旧版 JSON 导入时读取文件里保留的全部记录。旧版已经裁掉且缺少备份的内容无法重建。
- 普通删除先确认并保存最新会议状态，再持久化删除时间。普通会议接口只接受活动会议。已打开该会议的窗口收到移除事件后切换到可用会议。
- 永久删除由服务端再次核对会议编号、完整标题和这一次移入最近删除的时间。恢复后再次删除会产生新的确认依据。确认只适用于所选的这一场会议。
- 清理意图先写入数据库，随后清理本会议的附件和备份，最后在事务中移除会话、发言和执行恢复记录。若文件占用或应用中断，保留待清理状态，可重试，服务重启也会继续。完成后只保留不含标题、正文和路径的编号标记，防止滞后的写入把内容重新建出来。
- 数据目录内若保留了旧版迁移用的 `sessions.json`，永久删除也会清理其中该编号的记录，并保留同一文件里的其他会议。
- 圆桌自己保存的记录是可回读的跨窗口记忆。模型进程的临时状态、各家 CLI 的会话标识及尚未落盘的输出不构成恢复承诺。

## 后续设计

| 功能 | 拟议交互与验收条件 |
| --- | --- |
| 归档、重命名与置顶 | 会议菜单提供三个独立操作。归档后仍可检索、导出和恢复到活动列表。改名或置顶始终保留同一会议编号。 |
| 长历史检索和分页 | 列表按项目、状态和日期筛选，按需打开全文或加载更早发言。分页只影响一次读取的数量。在超过一千场的资料库中检查首屏耗时和检索完整性。 |
| 输入草稿与显式引用其他会议 | 输入草稿按会议和窗口保存，显示最后保存时间。跨会议引用由用户选取原发言或白板条目，同时展示来源会议，供下一轮讨论核对。 |
| 多设备与备份迁移 | 设计包含会议编号、发言、白板、附件和校验清单的可移植文件。导入先展示清单与冲突，允许保留副本。同步、共享和整库备份需独立设计访问范围、冲突处理与删除传播。 |

## 验收情形

1. 升级旧库并导入 60 场临时会议，其中一场含 550 条发言。重启、恢复和导出时核对首尾编号、顺序及附件内容。
2. 两个独立浏览器窗口连接同一服务，在其中一边修改白板和追问，核对另一边的变化。新建会议有独立记录。
3. 普通删除后重启，恢复所得的会议编号、发言、白板、附件与原记录一致。
4. 首次点击永久删除、输错标题和取消，均保留会议。确认后只清理目标会议。用过期的删除时间重放确认请求会被拒绝。
5. 清理中模拟文件被占用，重启后继续清理。重试相同请求可安全完成，已删除记录无法被旧的写入重新创建。
